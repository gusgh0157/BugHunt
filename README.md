# BugHunt — C++ 버그 추적 실습

버그가 **일부러 심어진** 작은 게임 코드 모음입니다.

- **1부: 호출 스택 입문 (랩 1~8)**: 프로그램이 죽은 순간 **호출 스택**을 거슬러 올라가 원인을 찾는 연습. 초보자는 여기부터 하세요.
- **2부: 심화 (랩 9~20)**: 메모리 오류, 미초기화, 레이스 등 증상이 덜 친절한 버그들. 데이터 중단점, ASan 같은 도구를 씁니다.
- **3부: 흐름 추적 (랩 21~28)**: 프로그램은 **멀쩡히 끝나는데 결과가 틀리는** 버그들. 디버거가 알아서 멈춰 주지 않으므로, 직접 중단점을 걸고 처음부터 한 줄씩 따라갑니다.

> 코드를 눈으로 훑어 정답을 찾지 마세요. 1·2부는 **실행해서 죽게 만들고, 디버거가 멈춘 곳에서부터**, 3부는 **직접 멈춘 곳에서부터 값을 확인하며** 추적하세요.

## 준비

1. `BugHunt.sln`을 Visual Studio로 엽니다. (VS 2022 17.13 이상이면 `BugHunt.slnx`를 열어도 됩니다. Rider 등 다른 IDE는 `.sln`을 쓰세요.)
2. 위쪽 도구 모음에서 구성을 **Debug**, 플랫폼을 **x64**로 둡니다.
3. **F5**(디버깅 시작)로 실행 → 메뉴에서 랩 번호 입력.
   - 매번 같은 랩을 돌리려면: 솔루션 탐색기에서 BugHunt 우클릭 → 속성 → 디버깅 → **명령 인수**에 번호 입력 (예: `1`)
   - Ctrl+F5(디버깅 없이 시작)나 exe를 직접 실행하면 디버거가 붙지 않아서 호출 스택을 볼 수 없습니다. 꼭 **F5**로 실행하세요.

# 1부: 호출 스택 입문

## 호출 스택이 뭔가요?

함수가 함수를 부르면, 컴퓨터는 "누가 나를 불렀는지"를 차곡차곡 쌓아 둡니다. 그 더미가 **호출 스택(Call Stack)**입니다.

```
printPlayer        ← 맨 위: 지금 실행 중인 함수 (여기서 죽었다)
showProfile        ← printPlayer를 부른 함수
openFriendList     ← showProfile을 부른 함수
cs01_profile
main               ← 맨 아래: 프로그램의 시작
```

**위에서 아래로 읽으면 "누가 나를 불렀나"**, **아래에서 위로 읽으면 "프로그램이 여기까지 어떻게 왔나"**입니다.

## 호출 스택 창 사용법

| 하고 싶은 것 | 방법 |
|---|---|
| 호출 스택 창 열기 | 디버깅 중 **Ctrl+Alt+C** (또는 메뉴 디버그 → 창 → 호출 스택) |
| 지역 변수 창 열기 | **Alt+4** (디버그 → 창 → 지역) |
| 다른 프레임으로 이동 | 호출 스택 창에서 줄을 **더블클릭** → 코드 창이 그 함수의 "호출한 줄"로 이동하고, 지역 창이 **그 함수의 변수**로 바뀜 |
| 숨겨진 STL/시스템 함수 보기 | 호출 스택 창 우클릭 → **외부 코드 표시** |

호출 스택 창의 한 줄은 이렇게 생겼습니다.

```
BugHunt.exe!lab1::showProfile(const std::string & name) 줄 40
└ 모듈 ┘  └ 네임스페이스::함수 ┘ └── 매개변수 ──┘     └ 소스 줄 ┘
```

- **노란 화살표**: 지금 멈춘 곳 (맨 위 프레임)
- **초록 화살표**: 다른 프레임을 더블클릭했을 때, "여기서 위 함수를 불렀다"는 위치
- **[외부 코드]**: STL, Windows 등 내 코드가 아닌 부분. 대부분 건너뛰고 **내 코드가 처음 나오는 줄**부터 보면 됩니다.

## 디버거가 멈추는 세 가지 모습

| 모습 | 의미 | 할 일 |
|---|---|---|
| "예외가 발생함: 읽기 액세스 위반" 같은 팝업 | 잘못된 포인터 등. 그 줄에서 바로 멈춤 | 호출 스택 창 열기 |
| **Debug Assertion Failed!** 창 | STL 등이 "이건 잘못됐어"라고 검사에 걸림 | **다시 시도(Retry)** 클릭 → (중단점 메시지가 나오면 "중단") → 호출 스택 창 열기 |
| "처리되지 않은 예외" / abort() | `throw`된 예외를 아무도 안 잡음 | 디버거가 throw 지점에서 멈춤 → 호출 스택 창 |

## 추적 4단계 (모든 랩 공통)

1. **어디서 멈췄나?** 호출 스택에서 **내 코드가 나오는 첫 줄**을 찾는다.
2. **무엇이 이상한가?** 그 프레임의 지역 창에서 이상한 값(nullptr, 0, 엄청 큰 수, 음수...)을 찾는다.
3. **그 값은 어디서 왔나?** 한 칸 **아래** 프레임(= 나를 부른 함수)을 더블클릭해서, 그 값을 넘겨준 곳을 본다. 출처가 나올 때까지 반복한다.
4. **진짜 원인은?** 멈춘 곳이 아니라 **이상한 값이 처음 만들어진 곳**을 고친다.

> 💡 핵심: **죽은 곳 ≠ 잘못한 곳**인 경우가 대부분입니다. 호출 스택은 "잘못한 곳"으로 거슬러 올라가는 길입니다.

각 랩을 풀 때 아래 기록표를 채워 보세요.

```
멈춘 함수:              
이상한 값:              
그 값이 온 프레임:       
진짜 원인:              
수정:                   
```

# 3부: 흐름 추적 (크래시 없음)

1·2부에서는 프로그램이 죽어 주었습니다. 디버거가 "여기야"라고 멈춰 주니 호출 스택을 거슬러 올라가기만 하면 됐죠.
실무 버그의 대부분은 그렇지 않습니다. 프로그램은 끝까지 잘 돌고, **숫자 하나가 틀릴 뿐**입니다. 이때는 **내가 직접 멈추고, 직접 따라가야** 합니다.

> 3부는 반드시 **Debug** 구성에서 하세요. Release는 최적화 때문에 줄이 건너뛰어지거나 변수가 "최적화되어 사용할 수 없음"으로 보입니다.

## 흐름 추적 4단계 (3부 공통)

1. **기대를 먼저 적는다.** "이 줄이 끝나면 `streak`는 2여야 한다"처럼, 따라가기 전에 각 단계의 기대값을 정한다. 기대가 없으면 틀린 값을 봐도 지나친다.
2. **틀린 결과에서 가장 가까운 곳부터 멈춘다.** 프로그램 맨 처음이 아니라, [FAIL]이 난 값을 만드는 함수 입구에 중단점을 건다.
3. **기대와 처음 달라지는 줄을 찾는다.** F10으로 넘기며 값을 확인한다. 달라진 줄이 함수 호출이면 그 함수 안으로(F11) 들어가 같은 일을 반복한다.
4. **"처음 달라진 곳"을 고친다.** 그 뒤에 나오는 틀린 값들은 대부분 그 결과일 뿐이다.

```
기록표 (3부용)
틀린 결과:              
멈춘 위치:              
기대값 → 실제값:         
처음 어긋난 줄:          
진짜 원인:              
수정:                   
```

## 3부에서 쓰는 도구

| 도구 | 하는 법 | 언제 |
|---|---|---|
| 중단점 + 한 줄씩 실행 | F9, F10 | 기본. 값이 줄마다 어떻게 변하는지 볼 때 |
| 함수 안으로 / 밖으로 | F11 / Shift+F11 | 의심 가는 함수 호출이 있을 때. 나오면 **자동 창**에 `함수명 반환` 값이 보임 |
| 커서까지 실행 | 원하는 줄에서 우클릭 → 커서까지 실행 (Ctrl+F10) | 중단점 없이 "여기까지만 가 줘" |
| 조건부 중단점 | 빨간 원 우클릭 → **조건** (예: `tick == 148`, `c.name == "Selene"`) | 반복이 수백 번인데 그중 한 번만 이상할 때 |
| 적중 횟수 | 빨간 원 우클릭 → 조건 → **적중 횟수** | "다섯 번째 호출에서만 멈춰" |
| 추적점 | 빨간 원 우클릭 → **작업** → 메시지 `{변수}`, "실행 계속" 체크 | 멈추지 않고 **순서**와 값을 기록할 때. 결과는 출력 창(Ctrl+Alt+O) |
| 조사식에 식 넣기 | 조사식 창에 `c.isVip()`, `&item`, `a.x - b.x` 처럼 입력 | 조건문의 각 부분을 따로 계산해 볼 때, 두 객체가 같은지 주소로 비교할 때 |
| 개체 ID 만들기 | 지역/조사식 창에서 변수 우클릭 → 개체 ID 만들기 (`$1`) | 특정 객체 하나를 계속 따라갈 때 |
| 다음 문 설정 | 노란 화살표를 끌어서 다른 줄에 놓기 (Ctrl+Shift+F10) | 같은 코드를 다시 실행해 보거나 분기를 건너뛰어 가설을 시험할 때 (상태는 되돌아가지 않음에 주의) |

3. `ft01_attendance.cpp`의 `calculateRewards`에서 `for (bool loggedIn : loginLog)` 줄을 클릭하고 **F9** → 빨간 원.
4. **F5**. 그 줄에서 멈춥니다. **Alt+4**로 지역 창을 엽니다.
5. **F10**을 한 번씩 누르며 지역 창의 `streak`와 `result.bestStreak`만 봅니다. 값이 바뀐 줄은 빨간 글씨로 표시됩니다.
6. 첫 바퀴에서 `streak`가 1이 됩니다. 기대대로입니다. 계속 F10. 둘째 바퀴에서 `streak`는 2가 되나요? → *처음 어긋난 줄*
7. 2가 안 됐다면, 1이었던 값이 **어느 줄을 지나면서** 0이 되었는지 다시 보세요. 다시 보고 싶으면 Shift+F5로 멈추고 F5로 처음부터 하면 됩니다.
8. 고치고 F5로 다시 실행해 [PASS] 두 개를 확인합니다.
